## Как запускать

1. Склонировать репозиторий
2. Заполнить `.env` на основе `.env.example`
3. Запустить проект через `docker compose up / docker-compose up`

## Как запускать тесты

1. Создать БД `docker exec -it db psql -U root -d scrap -c "CREATE DATABASE test;"`
2. Запустить тесты `docker exec -it app pipenv run pytest`

## Реализация
Парсер работает в celery задаче, запускаем парсер через апи, дергая ручку. 
Настроена пагинация, а также поиск через query параметры.
Проект реализует чистую архитектуру, используя DI, так как ограничен во времени без использования интерфейсов и тд.
Если приложение упадет, задача все равно обработана так как она передается брокеру и селери подхватывает ее,
также ввиду того, что реализован upsert данные при повторном запуске дублироваться не будут. Использовал селери потому что в будущем могли бы захотеть использовать запланированные задачи, а также потому что если бы мы делали наш парсинг через fastapi background tasks забирали бы ресурсы нашего апи.
Для ограничения параллелизма использовал семафор, чтобы не кидать кучу запросов нашему серверу и не перерасходовать наши ресурсы, кто знает сколько книг у них будет потом.
